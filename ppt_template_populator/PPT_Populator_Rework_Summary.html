Engineering summary — PPT Template Populator

Ek upload, ek click, poori presentation.

Document upload, manual ya automatic template selection, strict watsonx JSON validation, focused recovery aur formatting-preserving PPT population ek hi pipeline mein kaam karte hain. Yeh page current architecture aur latest runtime fixes explain karta hai.

120 tests passing Strict target schema enabled Manual + automatic selection

Teen badlaav

Har badlaav apni jagah independent hai, lekin teeno milkar poore intake se lekar generation tak ke flow ko simplify karte hain.

Intake

Topic box → Document upload

User ab sirf ek file upload karta hai — DOCX, PDF, TXT, MD, RTF, ya legacy DOC. Title, audience, tone, aur slide count sab document se khud-ba-khud nikal liye jaate hain. Koi extra field bharne ki zaroorat nahi.

Pehle: topic, demand, source content, audience, tone, sections — 8 alag text fields.
Storage

Elasticsearch → MinIO

PPTX binaries (aur ab uploaded documents bhi) ab MinIO object storage mein rehte hain. Elasticsearch sirf searchable metadata + vector embeddings rakhta hai — hybrid AI search wahi ki wahi taakatwar rehti hai, sirf ES ka size chhota ho gaya.

Pehle: har PPTX base64-encoded ho kar seedha ES document ke andar store hota tha.
Selection

Automatic + Manual toggle

Ek radio button: Automatic (AI top-5 candidates mein se best template chunta hai) ya Manual (user seedha dropdown se apni pasand ka template select karta hai). Dono modes same robust generation pipeline use karte hain.

Pehle: sirf automatic AI selection — koi manual override nahi tha.

End-to-end workflow

Jab user "Generate Presentation" click karta hai, ye 7 steps chalte hain — order matter karta hai kyunki har step agle ke liye data taiyaar karta hai.

1

Document upload & extraction

Uploaded file type detect hoti hai; python-docx / pypdf / striprtf se text nikala jaata hai. Title, body text aur ek heuristic desired slide count (~120 words/slide) automatically compute hote hain.

src/document_extractor.py
2

Document archive (optional)

Original uploaded file ka ek copy audit ke liye MinIO ke ppt-uploads bucket mein save ho jaata hai — best-effort, generation ko block nahi karta.

MinIO · ppt-uploads
3

Template routing

Automatic: extracted content ka embedding banta hai → Elasticsearch hybrid search (BM25 + cosine similarity) top-5 candidates deta hai → watsonx.ai unmein se best chunta hai.
Manual: user ne jo dropdown se chuna, seedha wahi use hota hai — retrieval/selection skip.

Elasticsearch · hybrid_search
4

Binary fetch + checksum

Selected template ka actual .pptx binary MinIO se fetch hota hai; SHA-256 checksum verify hoti hai taaki corrupted ya tampered file kabhi populate na ho.

MinIO · ppt-templates
5

Chunked content generation

Template ke required targets ko slides ke chunks (max 4 slides / chunk) mein todkar watsonx.ai se content generate hota hai. Output target mein sirf target_kind, target_id aur content allowed hain; invalid response ek controlled repair leta hai.

watsonx.ai · granite
6

Focused recovery (naya: graceful fallback)

Jo targets pehle round mein miss ho jaate hain, unke liye ek batched retry hota hai. Agar retries ke baad bhi koi target resolve nahi hota — ab pipeline crash nahi hota; safe placeholder text daal ke ek warning ke saath aage badh jaata hai.

Bug fix — neeche detail
7

PPTX populate & download

Validated content placeholder index ya Canva shape ID se likha jaata hai. Generated titles Aptos 36 pt, bold, centred, 1.0 line spacing aur Normal character spacing use karte hain. Populated slides se isolated stock photos remove hote hain, jabki repeated branding retain hoti hai.

UI error fix — "Unresolved required target keys"

Ye error aapke template mein bahut saare required table-cell targets hone ki wajah se aa raha tha — model kabhi-kabhi retries ke baad bhi kuch targets ke liye content nahi de paata tha, aur pipeline poori tarah fail ho jaata tha.

Pehle

Retries ke baad bhi agar ek bhi required target unresolved rehta, ResponseValidationError raise ho jaata — pura generation fail, kuch download nahi hota.

Ab

Unresolved targets ke liye safe placeholder text (existing text ya role-based generic filler) insert hota hai, aur ek warning list ke saath user ko exact slide/shape numbers dikhaye jaate hain — presentation ban jaati hai, review karna aasan.

Latest schema fix

Runtime error target objects ke andar copied metadata ki wajah se tha, template selection mode ki wajah se nahi. Isliye fix manual aur automatic dono modes par apply hota hai.

Model output

Model kabhi target ke andar slide_number aur role copy kar raha tha. Strict Pydantic model in fields ko Extra inputs are not permitted ke saath reject karta tha.

Safe handling

Prompt ab exact target shape batata hai. Parser matching redundant metadata ko remove karta hai, lekin conflicting slide number, invented IDs aur kisi bhi doosre unexpected field ko ab bhi reject karta hai.

Automatic selection update

Automatic mode ab generic audience aur tone ke saath uploaded PDF/document ka bounded content excerpt bhi retrieval query mein use karta hai.

Input

Document-aware query

Topic, complete demand, source content, audience, sections aur visual preference ek query banate hain.

Search

Hybrid ranking

Elasticsearch keyword relevance aur embedding similarity se maximum five compatible candidates return karta hai.

Decision

Deterministic best match

watsonx best candidate select karta hai. Same template tab repeat ho sakta hai jab wahi strongest match ho ya indexed choices kam hon.
